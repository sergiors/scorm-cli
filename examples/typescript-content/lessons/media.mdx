# Add media with context

Media components have different source rules. Local image and poster paths must resolve to assets inside the content package, though the parser also accepts absolute remote asset URLs. `<Image>` requires explicit alternative text, while `<Video>` embeds one supported hosted video.

## Image: asset source, required alt text

`<Image>` can be authored as a block or inline with paragraph text. Its required attributes are `src` and `alt`; `caption` is optional. Keep the alternative concise and useful for someone who cannot see the image.

<Image
  src="https://images.unsplash.com/photo-1500530855697-b586d89ba3ee?auto=format&fit=crop&w=1200&q=80"
  alt="A mountain landscape beneath a wide, open sky"
  caption="A landscape photo loaded from a remote image URL."
/>

Here the same component can sit in a sentence: <Image src="https://images.unsplash.com/photo-1500530855697-b586d89ba3ee?auto=format&fit=crop&w=1200&q=80" alt="A mountain landscape beneath a wide, open sky" /> illustrates the inline form.

## Video: supported hosted source

`<Video>` must use an individual YouTube or Vimeo URL. The provider is inferred from the URL in `src`; you do not need to specify it separately. Optional attributes are `title` and `poster`.

<Video src="https://www.youtube.com/watch?v=M7lc1UVf-VE" title="YouTube player API sample" />

<Video src="https://vimeo.com/76979871" title="Vimeo player sample" />

Local video files, direct media URLs, playlists, and unrelated hosts are not supported by this component.

<Callout variant="info" title="Make media usable">
  Provide meaningful image alternatives and a descriptive video title. If a local poster path is
  supplied, it must also resolve to an asset in the package.
</Callout>
